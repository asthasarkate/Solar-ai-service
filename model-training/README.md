# Model Training — Solara AI

## Directory Structure

```
model-training/
├── dataset_raw/           ← Raw downloaded datasets (manually placed)
│   ├── source_1_afroz/       Kaggle "Solar Panel Images"
│   ├── source_2_dust/        Kaggle "Solar Panel Dust Detection"
│   ├── source_3_pv_defect/   Kaggle "PV Panel Defect Dataset"
│   └── source_4_roboflow_crack/  Roboflow crack dataset
├── dataset/               ← Auto-generated by preprocessing script (NEVER edit manually)
│   ├── train/
│   ├── val/
│   └── test/
├── notebooks/             ← Jupyter notebooks (added later)
├── models/                ← Intermediate candidate models (not production)
├── results/               ← Evaluation outputs (confusion matrices, reports)
├── config.py              ← Constants only (IMG_SIZE, BATCH_SIZE, FAULT_CLASSES, etc.)
└── README.md              ← This file
```

## Dataset Placement

After running the setup, extract your downloaded datasets (from Kaggle/Roboflow) into the `dataset_raw/` subfolders:

- `source_1_afroz/` — Kaggle "Solar Panel Images"
- `source_2_dust/` — Kaggle "Solar Panel Dust Detection"
- `source_3_pv_defect/` — Kaggle "PV Panel Defect Dataset"
- `source_4_roboflow_crack/` — Roboflow crack dataset

Keep the internal folder structure as-is from Kaggle/Roboflow. The preprocessing script will read and remap them into our 4 fault classes.

## Model Export

The `model-training/models/` folder holds intermediate candidate models during experimentation. The final winning model must be copied to:

```
../../models/production_model.keras
```

This path (`ai-service/models/production_model.keras`) is what the live FastAPI service loads via the `MODEL_PATH` env variable.

## Config

All constants are in `config.py`:
- `IMG_SIZE = (224, 224)` — input image dimensions
- `BATCH_SIZE = 32` — training batch size
- `FAULT_CLASSES` — internal class names
- `LABEL_MAP` — maps internal names to display names
- `RANDOM_SEED = 42` — reproducibility
